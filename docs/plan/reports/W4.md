# W4 — Onboarding + ingest UI

Status: built and checked in the browser against the Next dev server (desktop 1440x900 and 375 wide, light
and dark). `npx tsc --noEmit` exits 0 for the whole app. **Not tested end to end against the API:** the
backend on :8000 was started before W2's `routes.tenancy` and W1's `routes.ingest` existed, so
`/api/me`, `/api/onboarding/schema` and `/api/ingest/*` all return 404 there. I didn't restart it. The UI
handles those 404s and shows a "Backend not ready" callout.

## For W3

```tsx
import OnboardingGate from "@/components/onboarding/OnboardingGate";
import IngestPanel from "@/components/onboarding/IngestPanel";

<OnboardingGate fallback={<Skeleton/>} onMe={(me) => …}>{dashboard}</OnboardingGate>
<IngestPanel projectId={projectId} onIngested={(job) => refreshOverview()} bare />   // bare = no outer glass card
```

- **Gate:** calls `GET /api/me` and sends users to `/onboarding` when `!orgDone`, or `/onboarding/project` when `!projectDone`. It writes the `vesper_onb` cookie so the proxy can redirect before paint next time. It never blocks when:
  - `/api/me` fails (404 or backend down), with a 4 s cap;
  - `authMode === "local"` (the P1 demo bypass);
  - the user clicked "Explore the demo project first" (`localStorage["vesper-onboarding-skip"]`);
  - the user isn't signed in.
- **IngestPanel** has three modes:
  - **Upload:** drag and drop multiple files, with a category select (drawing register, spec, method statement, RFI, permit, DPR, BOQ, contract, ITP, other).
  - **Paste text:** title + category, ⌘↵ to submit.
  - **Speak:** record with a live level meter and timer, play back, add a title, `POST /api/ingest/voice`, show the transcript.

  The job list merges optimistic local rows with `GET /api/ingest/jobs`, polls every 2 s while any job is queued/parsing/embedding/graph, and shows progress (`progress` 0..1 or 0..100, otherwise estimated from the stage).

## Clerk findings (action needed)

- This Clerk instance has **Organizations enabled with forced organization selection**. A signed-in user without an org has a `pending` session with task `choose-organization`. `auth.protect()` treats that as signed out, so Clerk sends them to `/sign-in/tasks/choose-organization`, and Clerk's own UI creates the org before our `/onboarding` loads. The flow still works: once an org is active, "Get started" goes straight to the org profile step.
- To keep org creation inside Vesper's UI, point Clerk's task URL at `/onboarding/org` in `app/app/layout.tsx` (not W4-owned). That's the `taskUrls` option on `<ClerkProvider>`; check the exact prop name in the Clerk v7 docs, since it isn't in the installed type declarations. Or turn off "force organization selection" in the Clerk dashboard.
- The personal-workspace fallback only saves on a backend in local header auth. With `CLERK_JWT_ISSUER` set, W2 requires a real Clerk org, and the UI explains that when the save fails.

## Known gaps

- End-to-end submit against the real API is untested (the :8000 routers aren't loaded).
- If a file field gets several files, all of them are ingested, but only the first is linked on the profile as `{name, docId}`, because the schema stores a single object.
- `optionsSource` (e.g. `templates?type=Checklist`) isn't fetched; the bundled `options` subset is shown.
- Drafts live in localStorage per org (`vesper-onb:{org|project}:{orgId}`). Files chosen in the wizard don't survive a reload.
- Dictation uses `POST /api/stt` (W5 is switching it to Sarvam). It needs a mic permission and a secure origin, which localhost is.
- The screenshot tool can catch the 0.5 s enter animation at opacity 0 when the pane is throttled. Real browsers render normally.
