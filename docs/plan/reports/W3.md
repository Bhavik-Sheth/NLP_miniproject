# W3: laptop dashboard UI and theme

Status: built, type-checked, production build passing. Visual browser check is **blocked by Clerk**; see "Verification".

## What was built

`/app` is now a laptop dashboard in the style of Linear, Rime and Sarvam. It has light and dark themes, a collapsible sidebar, a ⌘K command palette, a slowly animated background, and Liquid Glass on selected surfaces. The old phone console still works and has moved to **`/app/console`**. `/demo`, the landing page and the static demo build are untouched: they use `*.static.tsx` and none of the new routes.

### Components (`app/components/dashboard/`)
- `Shell.tsx`: sidebar (org switcher, project dropdown, grouped nav, shortcut hints, field console link, tour, collapse), top bar (breadcrumbs, ⌘K button, Backend/Voice/Memory status pills, theme toggle, `UserButton`), mobile nav sheet below 1024px, background, key handling.
- `context.tsx`: `DashboardProvider`. Installs the Clerk token getter synchronously, loads `GET /api/me` (falls back to the P1 demo project), stores the selected project, polls `/api/health` and `/api/v2/status` every 30 s, and holds sidebar/palette state.
- `theme.tsx`: `ThemeProvider`, `useTheme`, `ThemeToggle`. Uses a view-transition crossfade and re-applies `data-theme` after React's dev Strict Mode remount.
- `CommandPalette.tsx`: navigation, actions, theme, project switch, "Ask: …" and "Inspect retrieval for …".
- `DashTour.tsx`: new Driver.js tour across the dashboard. Runs once per user; replay from ⌘K or the sidebar.
- `primitives.tsx`: `useAsync` (flags missing endpoints), `DataTable`, `Sheet`, `Kpi`, `Panel`, `Badge`, `Notice`/`EndpointNotice`, `Segmented`, `Skeleton`, formatters.
- `Retrieval.tsx`: `LatencyBars` (waterfall from `timings`/`timingsMs` plus measured round trip) and `HitList` (score bars).
- `KnowledgeGraph.tsx`: dependency-free canvas force layout with pan, zoom, node drag, and hover highlighting of neighbours.
- `siteData.ts`: cached v1 record (drawings, RFIs, permits, observations), plus derived blockers, activity and a graph built from the site record.
- `icons.tsx`, `nav.ts`, `Gate.tsx`.

### API client
`app/lib/api-v2.ts`: typed client for every PLAN §4 endpoint, plus v1 `/api/drawings|rfis|permits` and `/api/v2/status`. Reuses `API_BASE`/`ApiError` from `lib/api.ts`. `setDashboardTokenGetter()` sets the token for both clients. `isMissing(e)` is true for 404/405/501. `SearchResponse`/`AskResponse` accept optional `timings`/`timingsMs` (ms per leg, e.g. `rewrite, embed, vector, bm25, rrf, rerank, llm, total`). **W1: please return one of these** so the inspector shows server-side latency legs; without it only the round trip is shown.

### Theme and tokens (`app/app/globals.css`, `app/app/layout.tsx`)
- An inline `<head>` script resolves the saved `vesper-theme` value (`light|dark|system`, default system) to `data-theme` on `<html>` before first paint. It also sets `data-theme-pref`.
- PLAN §6 tokens are defined for both themes on `:root[data-theme]`: `--bg --bg-elev --surface --surface-2 --glass --glass-border --glass-highlight --text --text-2 --text-3 --border --accent --accent-2 --ok --warn --danger --ring --shadow-lg --radius --radius-lg --ease`, plus `--border-strong`.
- The same tokens are exposed as Tailwind colours: `bg-canvas bg-elev bg-surface bg-surface-2 text-ink text-ink-2 text-ink-3 border-line text-accent text-ok text-warn text-danger`.
- Utility classes: `.glass`, `.glass-strong` (blur(24px) saturate(180%), inner top highlight, specular sheen, masked gradient rim for a refraction-like edge), `.card`, `.kbd`, and `dash-*` classes.
- **Scoping:** only elements inside `.vs-theme` paint with the tokens. The global `html, body { background:#000 !important }` rule is overridden only by `html:has(.vs-theme)`, so landing, /demo and auth stay dark. W4 pages should wrap in `.vs-theme` to follow the theme.
- `ClerkProvider taskUrls={{ "choose-organization": "/onboarding/org" }}` (coordinator request).
- `prefers-reduced-motion` turns off the background drift, orb, row and page animations.

## Fallbacks when v2 endpoints are missing
- **Overview:** counts come from v1. Hold points come from the recorded P1 site brief (`lib/demo-data.json`) and are labelled "from last site brief".
- **Ask memory:** on 404 it answers through the v1 engine (`/api/session` + `/api/turn`), labelled "v1 site engine · memory layer offline".
- **Graph:** built from the site record, with a toggle.
- **Other panels:** show an explicit "endpoint not live yet" notice.

## Backend endpoints depended on (state at hand-off, :8000)
- Live: `/api/health`, v1 record endpoints, `/api/v2/status`, tenancy (`/api/me`, `GET /api/projects/{id}/overview`, `POST /api/projects/{id}/invites`; `routes.tenancy: ok`). The overview's `recent` items are `{kind,id,summary,actor,createdAt}`; the Overview page normalises them.
- **Missing:** `routes.memory` and `routes.ingest` (`ModuleNotFoundError`), i.e. `POST /api/memory/search|ask`, `GET /api/memory/stats|graph|documents`, `/api/ingest/*`.
- **No v1 hold-points endpoint exists.** Overview/Permits use the brief snapshot until `/overview` returns `holdPoints` (a list would be better than a count).
