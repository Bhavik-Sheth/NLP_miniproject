## Endpoints (all JSON; `Authorization: Bearer <Clerk session token>`)

| Method + path | Notes |
| --- | --- |
| `GET /api/onboarding/schema` | No auth. Returns the schema |
| `GET /api/me` | `{user:{id,email}, org:{id,name,role,profile,completeness}\|null, orgs, projects, onboarding:{orgDone, projectDone}, authMode}`. `orgDone` = org row exists in app.db. `projectDone` = the org has a non-demo project (always true in `org_local_demo`). Lazily mirrors Clerk org membership into org_members |
| `POST /api/orgs` `{clerkOrgId, profile}` | 201 on create, 200 on update. With Clerk on, `clerkOrgId` must equal the token's active org. 422 `{error:"validation_failed", errors:[{key,message}]}`. Sends `welcome_org` on create |
| `GET /api/orgs/{orgId}` | Includes projectCount and members. 404 unless it is the caller's active org or the caller is a member |
| `PUT /api/orgs/{orgId}` | Admin of the active org only. Body `{profile}` is merged into the stored profile and revalidated |
| `POST /api/projects` `{profile}` | Needs an active org (409 if none, or if the org profile isn't saved yet). Validates, then 201 `{project, memory}`. Duplicate code within the org → 409 `duplicate_code`. Creator becomes project_members `owner`. Calls `memory.api.ingest_project_profile(org_id, project_id, profile)` synchronously if importable; otherwise `memory:{status:"pending"}`. Sends `project_created` |
| `GET /api/projects` | Org projects + projects the user is a member of + `P1` (role `demo`, `readOnly: true`) |
| `GET /api/projects/{id}` | `project` with `profile`, `completeness`, `members`, `invites` |
| `PATCH /api/projects/{id}` | Partial profile merge (`null` clears a field), then full revalidation. Returns `{project, memory, changed}` and re-ingests the profile when something changed. P1 → 403 |
| `POST /api/projects/{id}/invites` `{email, role, inviterName?}` | role ∈ manager/engineer/viewer/member. 201. Sends `project_invite` with link `APP_URL/onboarding/invite?token=…` |
| `POST /api/invites/accept` `{token}` | Binds the invite to the signed-in user, returns `{projectId, role}`. Extra endpoint, not in PLAN §4 |
| `GET /api/projects/{id}/overview` | `{project, counts:{drawings, rfisOpen, permitsActive, holdPoints, observations, documents, chunks}, recent, memory:{pendingJobs}, source}`. P1 reads site.db (drawings = v_latest_drawings, open RFIs, Active permits, v_open_hold_points, field_observations; also `drawingRevisions`, `permitBlockers`; `recent` includes observations). Other projects read app.db `documents`/`chunks`/`ingest_jobs` by `project_id` when those tables exist |

Access rules: a project is visible when its org is the caller's active org, the caller is in `project_members`
(by user id or invited email), or it is P1. Invisible projects return **404** (no existence leak). P1 is
read-only (403 on any write).

Validated curl results on :8002: me → org create 201 → invalid project 422 → create 201 (memory pending) →
list → get 200 → patch 200 → invite 201 → overview → other org GET 404 → P1 overview
`{drawings:10, rfisOpen:4, permitsActive:2, holdPoints:1, observations:4, chunks:6947}` → P1 PATCH 403.

The template at resend.com/templates/20ad030e-… must be **published** before `RESEND_TEMPLATE_PROJECT_CREATED`
is set to its id. `onboarding@resend.dev` only delivers to the Resend account owner; verify a domain before
sending invites to anyone else. Every send is logged to `email_log` with a SHA-256 of the recipient, never
the address or key, and runs in `BackgroundTasks` so it never blocks a request.

## Clerk dashboard steps

1. **Organizations → Enable**. Allow members to create orgs; roles `admin` / `member` (defaults).
2. **Sessions → session token version 2** (default for new instances). The org arrives as
   `o: {id, rol, slg}`, with `rol` lacking the `org:` prefix. v1 `org_id`/`org_role` is also supported.
3. **Sessions → Customize session token**, add `{"email": "{{user.primary_email_address}}"}` so emails
   and invite matching work without `CLERK_SECRET_KEY`.
4. Set `CLERK_JWT_ISSUER` (Frontend API URL, e.g. `https://<slug>.clerk.accounts.dev`) in backend/.env.local,
   and optionally `CLERK_AUTHORIZED_PARTIES=http://localhost:3000,https://<prod>`.

## Onboarding redirect (for W4 `app/proxy.ts` + pages)

1. Signed in with no active org → `/onboarding/org`: Clerk `createOrganization()` + `setActive()`, then call
   `POST /api/orgs {clerkOrgId, profile}` with a **fresh** token (after `setActive`, `getToken({skipCache:true})`)
   so the token carries `o.id`.
2. `GET /api/me`: `!onboarding.orgDone` → `/onboarding/org`; `!onboarding.projectDone` → `/onboarding/project`
   (wizard rendered from `/api/onboarding/schema`, `POST /api/projects`); otherwise `/app`.
3. For file fields, upload via W1 `/api/ingest/file` after the project exists (needs a `projectId`), then
   `PATCH /api/projects/{id}` with `{field: {name, docId}}`. Sensible order: create the project with text
   answers, then run the uploads step.
4. `/onboarding/invite?token=` → sign in → `POST /api/invites/accept {token}` → `/app/projects/{projectId}`.

## Notes for other workstreams

- **W1**: `from tenancy.appdb import connect`. Your `backend/memory/schema.sql` is applied on connect (use
  `IF NOT EXISTS`). Provide `memory.api.ingest_project_profile(org_id, project_id, profile) -> {status, ...}`
  that **returns quickly** (enqueue a job), because it is called inline in the request. The overview counts expect
  `documents`, `chunks`, `ingest_jobs` tables with a `project_id` column. Use
  `emails.send.send_email(to, "ingest_complete", {...}, f"ingest/{job_id}")` when a job finishes.
- **W3/W4**: use `Depends(get_identity)` semantics. 422 bodies list `errors[{key, message}]` using schema keys
  (repeater rows as `stakeholders[0].email`). `readOnly`/`isDemo` flag P1.
- **Everyone**: `require_project(pid, ident)` for reads, `require_project(pid, ident, write=True)` for writes.
